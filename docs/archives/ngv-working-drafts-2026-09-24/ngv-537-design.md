# #537 — additive affect evidence design

No locked contract change is needed. `record_affect` remains the sole Brief-phase writer of `analysis/affect.json`; `harmonic_evidence` is an optional, versioned JSON member. Existing AffectProfile stored layout and scorer policy stay unchanged. A new independent engine type owns this wire extension, source validation and presentation, shared by host writer and independently rerun pack gates. No public existing value type receives fields.

The host materializes exact analysis/measurement-proof/track/lyrics/alignment-source hashes and approved section indices/bounds plus local chord/key estimates, derived harmonic change rate, perceived tempo/beat counts, raw energy, and verified timed lyric excerpts. Missing instrumentation/onset/provider evidence is explicit. The agent supplies bounded section interpretation (fixed affect vocabulary, confidence <=0.7), support/conflict references to available signal families, uncertainty, harmonic interpretation and concrete visual choice. Empty affects plus a reason means abstention. No deterministic major/minor emotion map or DSP-to-normalized energy map is introduced. Track summary remains separate from section evidence. Aligned lyrics require matching measurement proof; unsupported timing is unavailable, not fabricated.

Original detected tags remain alongside explicit desired-affect override and reason. Omission preserves an existing override; explicit clear is separate. Versioned evidence must remain byte-preserved through legacy AffectProfile.save. Pattern fit uses the existing effective override and frozen normalization; agent confidence is corrected to the existing 0.7 contract cap. New evidence confidence is also honored without changing stored AffectProfile layout.

Canonical exact-byte Brief lineage already owns the whole affect artifact. The Brief and downstream gates re-read sources and reject stale evidence; legacy projects without the optional extension remain readable. The treatment writer materializes a deterministic, readable section-affect/visual-direction block from validated evidence; the independent Treatment gate verifies it. Shot List VisualArc validation requires the same per-section concrete visual decision, and prompt directives consume effective desired affect while retaining detected evidence. Existing Markdown artifact UI and both backends' shared phase instructions expose support, conflict, uncertainty, and override, avoiding a new UI surface or workflow phase.

Prepared tests cover contrast fixtures, abstention and missing signals, proof/source tampering, override persistence, legacy preservation, vocabulary/confidence, Treatment/VisualArc consumption and source invalidation. These are structural/contract fixtures, never subjective creative-quality proof. No local build/test/runtime or provider call; no CI/push/PR. The pack and additive engine contract versions will advance without raising the old ABI compatibility floor or changing project schema. Independent creative review and GitHub Actions remain pending.
