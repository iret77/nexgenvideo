# Generation batches

Present one numbered manifest in the existing chat decision area. Each item shows its purpose and the shared GenerationPackage projection, including readable model/provider, output count, destination and monetary estimate. Exact route, references, diagnostics and alternative selection live in details. Show the total and identify any item with unknown pricing. When pricing fails, offer **Approve without estimate** alongside **Ask agent to revise**, Decline and transient pricing retry. The explicit host approval records the exact unpriced item IDs; it permits unknown spending for this batch and acknowledges that its project budget cannot be guaranteed. It never invents a zero price, changes the project budget or grants later batches consent. Known item ceilings remain enforced. See [the visual specification](generation-approval.html).

Allow removing items before approval and declining the manifest. The primary action says `Approve X requests`, with X equal to the retained request count. Changing an item prepares a new package and a new manifest. Approval is one host-owned action over that exact manifest; the agent cannot approve individual items on the user's behalf.

Once approved, show completed count and each item's queued, submitting, running, complete, failed, canceled or blocked state. Keep generated media available for inspection. `Cancel remaining` cancels only items that have not entered provider submission. It does not discard completed media or cancel an already submitted provider job.

Restore the same status after reopening the project. Reconnects join an existing item. A known provider request resumes status retrieval and result download. An interrupted submission without a provider receipt is blocked for reconciliation; never silently resubmit it. A failed or blocked item does not stop unrelated queued items. A retry is a new item with a new explicit approval, and does not consume the original item's authorization again.

Use AppTheme and shared disabled button styles. Keep the card and progress in normal transcript flow. The persisted manifest, execution journal and central spend log are the authority for both the native card and agent status; no second batch budget ledger is introduced.
