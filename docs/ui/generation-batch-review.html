Generation batch review

Normative treatment for a compact, readable manifest in the existing Agent decision Dock. The reviewer can identify every output, reference and cost before approval without reading request JSON or losing Remove, Decline or Approve below a scroll boundary.

Binding relationship. This document specializes agent-chat.html, generation-batches.md and generation-package-review.md. Their ownership, spending, package identity, conversation binding and in-flow Dock rules remain authoritative.

Remove diagnosis

The reported interaction is not attributed to an overlay. Source inspection found two concrete faults in the previous card: the card and its body independently used the same maximum height without reserving header/footer space, and the shared busy state disabled Remove and Decline during pricing or route recovery. The replacement measures fixed regions once, gives only the body the remainder, and reserves the global edit lock for the approval commit. Supported-runner evidence must still activate the real Remove control by pointer and keyboard.

Surface and ownership

Agent panel (persistent in-flow siblings)
├── Conversation Bar
├── Transcript (its own scroll view)
├── Live Status
└── Composer Dock
    └── Generation batch decision
        ├── Header: count + shared output, destination and route summary
        ├── Body: the only batch scroll view
        │   ├── Group heading
        │   └── Compact numbered item → optional inline detail
        └── Footer: total/blocker + Decline + Approve
  • The decision replaces the composer and stays a normal Dock sibling. It is never a modal, transcript overlay, second approval surface or user-authored turn.
  • The header and footer never scroll. The body receives the available decision height after measured header, footer and theme spacing are subtracted. There is no nested item scroll.
  • Only an actual approval commit disables all mutations. Package recovery stays visible, blocks approval and its own duplicate recovery, but Remove and Decline remain available. Unknown pricing never disables Remove or Decline.

Manifest projection

GroupCharacter, Ensemble, Location, Prop, Look or Other and retained count. Grouping is a view-only projection from a leading purpose label. It never changes manifest order, item identity or canonical bytes. Global manifest numbers remain visible after grouping.

Expanded itemOrdered reference roles with real project-media thumbnails and an Open reference action; full route, output count, destination and price; then a Request details disclosure for compiled prompt, exact parameters, hashes, route evidence and package identity.
FooterVerified total and retained generation count. If any price is unknown, name the number of blocked items and recovery action. Decline remains enabled. Approve remains visible, unmistakably disabled, and carries a visible reason outside the disabled control.

Interaction and state

  • Remove targets the item ID, not its displayed group position. The host atomically creates a new manifest, transfers the originating conversation/tool binding to the new manifest ID, then publishes the new pending state. Count, groups, total and approval eligibility update together.
  • Removing the last item resolves exactly like Decline: no submission, no empty manifest and a completion routed to the owning conversation. Decline always returns to that same conversation.
  • Expanded state is view-local and keyed by item ID. Removing an expanded item clears only that stale key. Route or pricing recovery preserves expansion when the item identity remains.
  • Reference thumbnails use current project media matched by the immutable reference receipt. Missing previews show a labeled media placeholder, never a filename pretending to be an image. Opening a reference selects the actual project asset; it does not approve or alter the package.
  • Approve binds the exact retained manifest ID. It is disabled while any retained item has no verified monetary ceiling, while recovery is running or while commit is running. A visible blocker states why. Existing #529 Retry pricing and route-change recovery remain in item detail.
  • Errors remain inline in the footer and release controls after the failed operation completes. No optimistic UI may leave the manifest identity and conversation origin out of sync.

Implementation constraints

  • Native UI uses AppTheme for every spacing, font, weight, radius, border, opacity, icon frame, shadow, color, animation and component dimension. Missing tokens are added first.
  • A layout primitive computes the body allocation from the decision bound and measured fixed regions. Do not restore two competing maxHeight frames or derive Dock size from transcript scroll geometry.
  • The existing package, manifest, recovery, journal, spend log and Agent conversation bindings remain the only authorities. The projection introduces no editable copy or second identity.
  • All visible controls perform their label. Shared disabled styles remove active contrast and hover response. Technical IDs and request evidence stay behind Request details.

Acceptance criteria

  • At 1, 13 and 50 items, short and long purposes, closed and open details, 240/400/640-point panels and increased text size, actions are not covered and horizontal scrolling is absent.
  • Before approval, the reviewer can identify what is generated, the real visual references, route deviations and the verified total without expanding JSON detail or reading the transcript.
  • With unknown pricing, Approve is visible and disabled with a reason while Remove and Decline respond by pointer and keyboard. Removing the last unknown item can make the retained total valid.
  • Removing first, middle and last items preserves global numbering semantics, new manifest identity, owner conversation and correct final resolution. Decline submits nothing.
  • Runtime evidence on the supported Actions runner activates Remove by a real UI click and by a keyboard event, observes count/identity changes, and proves the controls are not blocked by layout, hit-testing or main-thread work.
