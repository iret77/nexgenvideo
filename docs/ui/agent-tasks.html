Task-oriented agent interaction

This is the primary agent-surface contract for #556. It supersedes the conversation-bar and free-composer hierarchy in agent-chat.html; that document's transcript grammar remains applicable to Diagnostics.

The persistent in-flow regions are Tasks bar, current Task Result, Live Status, and the current interaction dock. Only one of task instructions, host intake, structured dialog, gate approval, spend/batch approval, or backend recovery owns the dock.

A named task is required before instructions can be sent. Brief and project-change tasks accept purpose-bound prose. References and imports use the existing media picker. Required instructions disable Run Task while empty. Running tasks retain a visible Stop Task action. Failed submissions retain inputs. Closing and reopening the interaction panel preserves the current decision’s text, toggles, custom answers, files, and selections. Explicit abandonment or a different decision clears those inputs. Closing a task retains its draft for explicit reassignment. Unknown or malformed dialog schemas are rejected before presentation; no confirmation state is created. The existing tool loop returns the schema error to the agent so it can submit a corrected structured dialog.

Decisions is a read-only receipt history. Diagnostics is a separate read-only transcript with tool detail, images, and copy actions. Neither grants approval. Sessions is secondary recovery navigation, guarded against switching or deleting while a decision or running task owns the session. The existing agent service, sessions, phase jobs, and native writers remain authoritative. Session-owned clarification dialogs restore their exact dialog, fields, references, choices, and original session from saved project chat data. Loading does not send an answer or approve anything; completion still uses the existing guarded handler. External MCP dialogs cannot acquire an in-app session through reload.
