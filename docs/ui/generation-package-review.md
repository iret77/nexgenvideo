# Generation package review

Use the existing in-chat spend card. The provider/model controls select an exact route; changing either prepares a new request before the primary action becomes available. Preparation does not reserve money or submit a content generation. Show preparation failures in the card with a retry action.

Below the route selector, show the prepared generation's subject, output count, estimated amount when known, destination and ordered reference list. Label unknown pricing explicitly. Expandable details show the compiled provider prompt, exact request parameters, input hashes and source route evidence. Copying the provider prompt copies only the prompt; copying package details includes the complete package. The package is an execution projection, not an editable second plan.

Keep the existing approve/decline actions. Approve stays disabled while the selected route has no prepared package or its input preflight fails. Approval binds the package hash; input, direction, destination, output-count and route changes require renewed preparation. Missing pricing does not invalidate an executable request; unknown-price batch approval follows [the explicit approval contract](generation-approval.html).

References resolve through the same host path during preparation, preview, approval and batch restoration. Library references retain their asset identity and media type, including production-route inputs whose exact project path must also match their prepared binding. Synthetic pipeline references resolve their recorded pipeline-relative path; synthetic frame references resolve the exact binding in their prepared plan. These two synthetic reference types do not need a library entry. Each source remains a real, project-local file with its original hash; image references also remain readable images. The input archive supplies the exact submitted bytes, including any prepared transformation, but cannot replace a missing library identity or missing/changed project source. Both source and archived hashes are checked before execution authority is granted.

The composer takes visual directives from the ledger and approved production artifacts, never directly from a pattern's lighting, color or craft prose. Explicit contradictory directives fail composition before submission. The compiler-input fingerprint includes the composition-policy revision, so packages prepared under the previous policy require recompilation and renewed review.

Use AppTheme and shared disabled button treatment. Loading and error content stays in the card's normal flow. Do not add another modal, another user turn or a second approval dialog. Future batch presentation uses the same package per item and remains owned by the batch authorization implementation.
