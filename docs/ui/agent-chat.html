Calm, task-oriented Agent

This is the normative information architecture and visual grammar for the NexGenVideo Agent. Conversation content is primary, current work is secondary, and utility chrome is tertiary. A user task and everything it produces form one stable turn.

Turn anatomy and rhythm

  • A turn contains authored user intent when present, assistant prose or one result document, one current/completed activity summary, and its durable receipts.
  • Intra-turn spacing uses 4–12 pt roles. Inter-turn spacing is 20 pt plus a quiet divider. Consecutive receipts within one phase use 2–4 pt and one group rail.
  • Completed activity is collapsed by default. Current work may expand only at the owning tool-call position. Disclosures never nest.
  • Streaming replaces the current result/activity in place using stable identity. It does not append status rows or move a reader who is pinned away from the bottom.
  • Plain assistant prose has no card chrome. Structured content uses one bounded result document, never an arbitrary peer-card stack or duplicated Markdown.

Composer Dock state machine

composing | clarification | workflow-intake | gate-approval | spend-approval | submitting | recoverable-error. Exactly one state renders. A decision has a labeled primary action and distinct Skip, Done, Clear item, Not yet, Decline, Approve, Generate, and Cancel actions. Required fields expose a disabled reason. Decision content is bounded to 280 pt with one internal scroll region; the transcript never gains a nested scroll view.

Status precedence

authentication/unavailable → terminal failure → cancellable generation → phase run → submitting decision → action required → streaming/activity → backend checking → ready. Detailed errors stay in the Dock or owning turn. A visible decision owns “Action required” and suppresses the separate status line. A visible running activity owns “Working.” Ready is one compact line.

Conversation chrome and utilities

  • The bar shows labeled History, labeled New, and labeled Workflows when available. History contains every saved/open conversation, search, running/action-required cues, switch, close, and explicit delete.
  • Workflows and backend/model information live one disclosure deep and appear directly only when they affect the current task or decision. Attach/import/reference remain one paperclip menu.
  • Latest is an in-flow labeled action only while the reader is away from the bottom. It relays a scroll request by state and never overlays or resizes the transcript.

Responsive, keyboard, motion, and accessibility

  • 240 pt: History, Workflows, and New remain labeled. Result key-value rows stack. Decision actions wrap without hiding the primary action.
  • 400 pt: the full conversation bar fits; result documents keep a two-column key-value grid. 640 pt: prose remains capped at the shared chat-column width.
  • Reading order is conversation bar → turns (intent, result, activity, receipts) → live status → Dock. VoiceOver groups each turn and each dock state as one landmark with state and primary action.
  • Keyboard: ⌘N New; ⌘⇧H History; Esc cancels only when allowed; Return submits only in composing; Tab traverses one coherent dock; destructive Delete is never the Close action.
  • State always has text and symbol, not color alone. Text contrast follows AppTheme. Reduce Motion uses opacity only; no scale/move transition shifts the transcript/Dock boundary.
  • The observed transcript ScrollView, bar, status, and Dock are persistent acyclic in-flow siblings. No shared ZStack, overlay, scroll-edge effect, geometry callback, or nested transcript scroll.
