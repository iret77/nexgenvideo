Calm, task-oriented Agent chat

Binding information architecture, state ownership, visual grammar and responsive behavior for the canonical NexGenVideo Agent panel.

This contract reorganizes existing chat capabilities. It does not add a second Pipeline, change workflow semantics, turn chat into the application spine, or move artifact truth into the transcript.

Approval gate. Implementation of issues #428–#432 begins only after this document is explicitly accepted. Later intentional UI changes update this artifact in the same change.

Canonical hierarchy

The four panel regions are persistent, in-flow siblings. The observed Transcript scroll view never shares a ZStack, overlay, scroll-edge effect or alignment container with the Conversation Bar, Live Status, Latest action or Composer Dock.

Turn semantics and reading order

  • A turn is an explicit semantic projection with a stable identity. A message role alone is not a turn boundary.
  • A visible user-authored request becomes User intent. Host-authored kickoff text stays hidden and may anchor a system-origin turn with no false user row.
  • Workflow records, attachments, skips and approvals are Receipts. They never render as user-authored turns even when their storage carrier has a user role.
  • New events carry a host correlation identity such as turn ID plus phase/job identity. Legacy transcripts project deterministically: visible user prose begins a turn; hidden kickoff begins a system-origin turn; a workflow receipt attaches to the preceding correlated turn; an orphan assistant result becomes a system-origin turn rather than invented intent.
  • Completed visual and VoiceOver order is User intent → Assistant result → Activity summary → Receipts → Notices. While no result exists, active Activity follows intent immediately; when the result arrives it is inserted before the same stable activity identity.
  • Turns use spacing and typography for hierarchy. They are not universal nested cards.

Four transcript families

FamilyNormative treatment
ActivityOne quiet summary row. One disclosure reveals a flat ordered list of steps, arguments and results. There is no disclosure inside another disclosure. Host tool presentation and runner events supply labels; model prose does not become operational status.
ResultOne logical assistant result per turn. Plain prose stays unframed. Structured content forms one bounded document surface, not one card per block. Generated media, provenance and durable Copy/Open/Reveal actions belong to this result.
ReceiptCompact, non-interactive host history grouped by turn or phase. Attached, provided, skipped, completed, failed and needs-action use explicit words and non-color symbols. A green checkmark is not the universal meaning.
NoticeA turn-bound interruption or failure with one owner and, when available, one recovery action. Agent-facing gate refusals are translated; tool names and artifact paths are not exposed unchanged.

Structured results and #135 compatibility

  • show_blocks remains the single schema-validated rich-result tool. Plain prose remains valid and is never heuristically converted into native blocks.
  • New output uses a versioned, bounded document shape with fixed slots: optional headline, body text, status badges, key-value groups, optional callout and generated artifacts. Each slot has a declared maximum. Model-authored symbols and arbitrary block order are excluded.
  • Every variant declares enums, required fields and additionalProperties: false. Invalid current-version input returns a tool error and presents no partial rich UI.
  • Prose and valid structured data in one turn are folded into one Result. A second show_blocks call cannot create a second primary result.
  • Versionless saved payloads use a dedicated legacy decoder and remain visually stable. Tightening the current decoder must not erase saved rich results.
  • New output has no phases-ref. Pipeline is the canonical phase surface. If a legacy saved payload contains that type, it becomes one compact non-interactive Pipeline reference/open action, never a phase rail.
  • Transcript actions may copy, open or reveal durable artifacts. Approval, selection and clarification controls remain in the Dock or their canonical artifact surface.

Composer Dock and #96 compatibility

#96 keeps three roles in three places: pending control in the Dock, visual choices on canonical application surfaces, and history as a compact non-interactive Receipt.

Dock stateRule
CommittingThe current decision remains visible with its controls disabled and a specific committing label. Conversation switching is unavailable until the host mutation settles.
DecisionClarification, file intake, gate and spend approval replace the composer. Exactly one can be active. It belongs to the selected conversation and cannot be answered from another.
RecoveryWhen no decision is pending and the backend cannot run, one compact recovery surface replaces the composer and owns the sole Agent Settings action.
ComposerDefault. Draft, mentions, staged function, height and focus are owned per conversation. Switching restores that conversation's state; it never carries a stale draft or staged function into another chat.
  • A text-bearing decision reuses the dock editor behavior with a decision-local binding. The conversation draft remains untouched and returns with its height and focus after completion, cancellation or Escape when cancellation is allowed.
  • Decision content has an AppTheme maximum height and one internal scroll view. The Transcript remains a separate sibling scroll view.
  • Library results inside intake are bounded and searchable. The intake drop target remains a leaf SwiftUI drop target; no parent SwiftUI .onDrop spans nested targets.
  • Streaming may replace Send with Stop. A detached paid generation does not take over the Dock; its concise state and Cancel remain in Live Status, so composing stays available.
  • Raw prompts never reach a content model. Dock submissions use the existing prompt engine and schema-validated tool contracts.

Repeatable optional intake

  • The title numbers exactly one current item. Every shown file belongs to that item.
  • Attach is enabled only after every required field is present: a usable name and at least one accepted image.
  • The first empty item has visible Skip. After one attached item, the next empty item has visible Done. Neither action is overloaded onto Attach.
  • A partial item disables completion and dismissal and exposes Clear item. Clearing restores the correct empty first/next state.
  • Disabled buttons use shared muted text, non-accented background, reduced opacity and no hover response.

Pipeline progress contract

  • An active run_phase specializes its Activity into one compact, always-expanded progress element at that tool call's transcript position.
  • It names phase, original user-facing source filename, current runner stage, completed/total declared stages and next stage. Storage hashes never appear.
  • Only runner-emitted stage boundaries advance progress. There is no invented percentage, ETA or fake completion animation.
  • The canonical Pipeline panel only marks the phase Running. It never duplicates detailed progress. All project gate mutations stay unavailable while the runner is active.
  • Completion collapses to the normal Activity summary. Failure remains a concise failed Activity whose one disclosure contains technical detail.

Conversation Bar and session ownership

  • There is one conversation model: a title/menu control opens a bounded searchable switcher. There is no horizontal tab strip plus History popover.
  • The bar contains a flexible current title, visible New, reserved in-flow Latest and visible More. More contains Workflows in exactly one place and Close conversation.
  • Close removes a conversation from the open set but keeps its history. Delete is a targeted, confirmed action in the switcher; it is never a synonym for Close.
  • Full titles and timestamps appear in the switcher. The bar truncates in the middle only when space requires it; a fixed character prefix is not the title model.
  • Running, Needs action and Unread result are service-owned states keyed by session ID, shown with text plus a symbol. They are not inferred by the view from saved message prose and are not persisted as durable transcript truth.
  • A pending decision remains bound to its owner conversation. Switching may reveal another conversation's own Dock, but can never show or resolve the first decision there.
  • Latest occupies a permanent in-flow slot. It appears by opacity/hit-testing only when the user is away from the bottom, and relays a state request to the Transcript. It never overlays or captures the scroll view.

Implementation constraints

  • Native implementation uses only AppTheme spacing, type, weight, radius, border, opacity, icon size, shadow, color and animation constants. Add turn spacing, receipt spacing, decision maximum height and conversation geometry tokens before use; do not hardcode them.
  • Disabled controls use the shared button style and do not retain active contrast or hover.
  • Agent-visible copy follows the actual app interface localization. OS locale, project content, filenames, lyrics and prior generated prose never switch it.
  • Header, observed Transcript, Live Status and Dock are persistent in-flow siblings. No scroll-geometry callback owns view insertion, animation or secondary-layer alignment.
  • The exact current session/runtime, paperclip, mentions, drop, paste, send, stop, drafts, staged function and Pipeline runner contracts remain functional.
  • Every visible control performs exactly the named action. Symbols shown in mockups are approximate; the native host owns SF Symbol selection and accessible text.

Acceptance criteria

  • Every mockup state below renders the complete four-region panel at 240, 400 and 640 points.
  • Short and long plain-prose results retain the same unframed Result grammar and readable measure; content length never selects a second visual dialect.
  • A 34-turn conversation remains scannable, keeps stable turn identity, preserves the user's scroll position and exposes a labeled Latest action without overlay.
  • No host receipt or hidden kickoff appears as user-authored intent.
  • At most one primary Result, one active Activity summary and one decision Dock are visible per turn/panel state.
  • Every duplicated state has one owner according to the ownership matrix.
  • Pending decisions, drafts, mentions and staged functions cannot cross conversation identity.
  • The repeatable intake first-empty, partial and post-attachment empty states satisfy every locked action rule at all three widths.
  • Pipeline progress answers phase, original file, current stage, count and next stage without expanding anything or cloning Pipeline.
  • Keyboard and VoiceOver traversal follow the tables above; Reduce Motion changes no information.
