Generation batch review

Binding visible contract for the native NexGenVideo decision card. Values mirror AppTheme; all native styling uses its tokens.

  1. Keep one bounded vertical decision-body scroll. Header, total, Remove, recovery controls, Decline, and Approve are persistent in-flow siblings outside it. Do not add nested scrolls or scroll-attached overlays. Fit the existing 318-point decision height; stack action buttons when width is narrow.
  2. Preserve prepared item order for 1, 13, and 50 items. Number each item once for the review lifetime; removing item 2 leaves 1, 3, 4. A quote retry changes immutable batch identity without renumbering surviving items.
  3. Show common provider and model once. Each compact row retains purpose, output count, destination, and its own verified EUR price. Mixed routes show per-row metadata. Long purpose text truncates in the collapsed row and remains readable in Details.
  4. Show image-reference thumbnails in a non-scrolling strip of up to three images with a remaining count. Expanded Details exposes every reference, full purpose, provider prompt, request data, and technical diagnostics. Missing previews remain labeled placeholders.
  5. Checkbox selection is available to all rows, including unpriced rows. Remove acts on selected rows through the same handler for pointer activation and the focused review's Delete command. Space toggles a focused checkbox; Details is a native keyboard-accessible button. Do not install a global Delete shortcut or intercept text editing.
  6. Any unpriced item disables batch approval and hides the numeric total. Show “Price unavailable”, Retry Pricing, and Change Route. Retry quotes all unpriced pending items; Change Route acts only on selected unpriced items. Busy states disable approval, selection, removal, decline, and recovery without active hover/contrast.
  7. A single prepared request without a verified estimate also disables approval. Keep “Prepare request again” visible in its footer and use the selected option's existing preparation action. Never present unknown cost as zero.
  8. Expose concise user-facing failure copy. Raw provider/gate errors, paths, hashes, and request parameters belong only in expanded diagnostic detail. The actions never imply spend authority before native approval.
