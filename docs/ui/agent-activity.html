StateVisible behavior
Agent respondingName the actual tool or response activity. Elapsed time and last received event are distinct. Unknown totals use indeterminate progress; never invented percentages or ETA.
Phase or batch runningProgress derives from runner boundaries or completed journal entries; the count names its scope (“stages in this phase”, “generations in this batch”). Show activity lists runner stage boundaries with their offset from the start. A single provider call has unknown total work. Phase cards use audio wording only for audio-analysis stages.
Provider job runningEvery successful provider status poll that reports the job as queued or running updates “Provider reports running · … ago”. It is liveness only: it never advances progress or changes the current step, and “Last progress event” stays unchanged until a real step or journal event arrives. Providers without a status channel show “No progress event yet”.
No event for 60 seconds“No response for 1:00. The current state cannot be confirmed.” Silence counts from the latest real event or provider confirmation. A UI timer never counts as backend liveness. Receiving another event or confirmation clears uncertainty.
FailureA failed phase reads “<Phase> failed”; a failed agent request reads “Agent request failed” with the error below. Failure is never labelled “Stopped”.
Decision pendingShow Action required and the named decision in the bottom dock. Approval, revision permission and paid generation are separate decisions. Agent prose never determines the authoritative state.
Repeated planning failuresAfter three failed canonical writes without a successful write, stop the retry loop. Show Retry planning in the same dock with optional diagnostics. Retry reads current contracts; it does not authorize new spending or rewind approved work. External callers get an explicit permission to resubmit, without starting an unrelated chat.
StoppedStop agent stops orchestration. Submitted provider jobs may continue; never label this as a guaranteed provider cancellation.

Accessibility and verification

Status and numeric progress are readable text. Reduced Motion suppresses indeterminate animation; elapsed time is never announced as a continuous live region. VoiceOver announces status title changes and the transition into and out of the unconfirmed state, never timer ticks. Regression fixtures cover real-event silence, bounded failures and external recovery. Native Actions acceptance must verify narrow panes, larger text, VoiceOver and actual status transitions. No local app verification is implied by this spec.
